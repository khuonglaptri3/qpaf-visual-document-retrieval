## Why

[M2.8-001](m2.8-score-cache.md) passed every integrity check but left one train
query uncovered. Its positive page ranked 271/273/769, outside every top-200
list, while all three channels ranked pages of the correct PDF first. The
frozen gate needs zero uncovered queries, and the protocol forbids dropping the
query or injecting the positive. A003 fixes the pool in a way that is label-free
and keeps the cap. It was proposed after the failure was seen, so it is
recorded as post hoc ([follow-up note](../superpowers/reports/2026-10-21-m28-uncovered-query-followup.md)).

## Rule (`qpaf_m28_top_document_expansion_v1`)

For each query:

1. Keep `C0`, the exact M2.8-001 top-200-per-channel union.
2. Rank every corpus page per channel by raw score (descending, ties by
   ascending page ID) and compute `RRF = 1/(60+r_bm25) + 1/(60+r_dense) + 1/(60+r_visual)`,
   summed in float64 in that order.
3. Score each PDF by its best page's RRF. Pick one PDF (ties by ascending
   document ID).
4. Add its pages missing from `C0`, highest RRF first (ties by page ID), up to
   `600 − |C0|`.
5. Recompute per-query min-max normalization on the new union.

The builder takes no labels and treats query IDs as row keys only. This matters
because ViDoSeek query IDs contain the source PDF's stem. A unit test renames
the queries and checks that the candidates do not change. Page → PDF uses the
canonical M2.6 ID `{pdf}_page_{NNNN}`.

## Phases

`scripts/run_m28_expansion.py` runs three phases with fixed label boundaries:

| Phase | Reads labels | Does |
| --- | --- | --- |
| `--develop` | development qrels, after the freeze | Verifies the three M2.8-001 `scores.npy` against the Git-tracked portable manifest; requires the rebuilt `C0` to match the M2.8-001 freeze (counts, IDs, array hashes, candidate keys); builds, freezes (create-once) and replays the expansion; then audits train/validation coverage. |
| `--finalize` | test qrels, coverage only | Refuses unless development passed (no tuning). Writes coverage, M2.4/M2.5 loader checks, handover and the bundle byte manifest. |
| `--verify` | same, read-only | Replays everything and creates nothing. |

The freeze writes six Parquet files: the four from M2.8, plus
`candidate_expansion_log.parquet` (one row per added page: PDF, priority, RRF,
reason) and `candidate_expansion_queries.parquet` (the selected PDF and counts
for every query). The schema is `qpaf_m28_candidate_freeze_v2`. The trainer
cache stays `qpaf_score_rows_v1`, so M2.4 and M2.5 load it unchanged.

## Measured run on 2026-10-21

Run `RUN-QPAF-M2_8-EXPANSION-001-20261021T042029Z-A01` took about 43 s locally
on CPU, with no GPU and no re-encoding.

| | M2.8-001 | M2.8-002 |
| --- | ---: | ---: |
| Candidate rows | 549,689 | 551,764 (+2,075 over 530 queries) |
| Per-query candidates (min / mean / max) | — | 388 / 483.2 / 579 |
| Macro recall | 0.999124 | 1.0 |
| Uncovered (train / validation / test) | 1 / 0 / 0 | 0 / 0 / 0 |

For 612 queries the selected PDF was already fully inside `C0`, so no page was
added. No query had `C0` at the 600 cap. The failing query selected its own PDF
and gained 7 pages (448 → 455), with page 7 first.

## M2.7 binding

`configs/m2.7/input_binding.json` pins the unchanged `matched.json` and binds the
M2.8-002 inputs ([m2.7-003](../../evidence/revisions/m2.7-003/README.md)).
`scripts/verify_m27_binding.py` rehashes every input against the handover and
reruns the synthetic parity checks. It then replays each method's seeded batch
order on the real records for all three seeds, without training.

## Limits

- Coverage is a property of the candidate pool. Extra pages can be distractors
  for every method, and nothing here shows that nDCG@10 or learned QPAF improves.
- QARF, QPAF and every M2.5 baseline must use this same pool and must cite the
  policy ID.
- The independent review of A003 and the named D1 review are still pending.
