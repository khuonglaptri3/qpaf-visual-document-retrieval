# M2.4 — Pipeline huấn luyện/đánh giá learned tối thiểu

Owner: Tấn Phát · Phụ thuộc: G1 · Code: `src/qpaf/m24/` · Config: `configs/m2.4/pipeline.toml`

M2.4 nối lõi phương pháp M1.2 (13 features → gate → softmax → fusion → loss)
với dữ liệu dạng cache: dataset → batch → trainer → evaluator → checkpoint →
telemetry, cùng các đường lỗi. M2.4 **không** chạy pilot QARF/QPAF (M3) và
**không** khóa matched config (M2.7).

## Hợp đồng đầu vào

| Đầu vào | Định dạng | Ghi chú |
|---|---|---|
| Score rows | parquet/csv `qpaf_score_rows_v1`: `query_id, page_id, bm25_score, dense_score, visual_score` | Chỉ đọc đúng 5 cột; cột `relevance` trong cache cũ bị bỏ qua |
| Query text | JSON `{query_id: text}` | Dùng cho feature `query_length` |
| Qrels | JSON `{query_id: {page_id: relevance}}` | Nhãn = `relevance >= positive_threshold`; chỉ vào loss/metric |
| Splits | thư mục `train_ids.txt`, `val_ids.txt`, `test_ids.txt` (định dạng M1.3/M2.1) | Test chỉ dùng kiểm disjoint |

Ranh giới nhãn: score rows và qrels là hai nguồn riêng, nên nhãn không thể đi
vào `build_features`. Rows của test không được dựng thành record.

## Các bước kiểm (fail-fast, `DatasetError`)

Split chồng nhau · row thuộc query ngoài mọi split · trùng `(query, page)` ·
điểm NaN/Inf/bool · thiếu query text · qrels không có positive · query không có
candidate (uncovered) · vượt `max_candidates` (600, theo contract M2.8).

## Huấn luyện

- Gate `FusionGate` của M1.2, float64, CPU, 1 thread, deterministic algorithms.
- QARF = granularity `query`, QPAF = `page`; cùng seed khởi tạo nên tham số ban
  đầu giống hệt (`build_model` không làm lệch RNG toàn cục).
- Adam, clip grad norm, thứ tự batch từ `torch.Generator` có seed; trạng thái
  generator lưu trong checkpoint để resume cho kết quả bit-identical.
- Batch không có query nào vừa có positive vừa có negative thì bỏ qua và đếm.
- Loss/gradient/tham số không hữu hạn → `TrainingError`, run thất bại có ghi lại.

## Chọn model và metric

Sau mỗi epoch đánh giá validation; `best.pt` = epoch có `ndcg_at_10` cao nhất,
hòa thì giữ epoch sớm hơn. Metric: nDCG@10 (binary gain), Recall@1, Recall@3,
MRR@10; xếp hạng score giảm dần rồi page ID tăng dần; mẫu số IDCG/recall gồm cả
positive nằm ngoài candidate union.

## Checkpoint

`last.pt` mỗi epoch, `best.pt` khi cải thiện; ghi atomically. Payload gắn
`config_sha256`, method, tên 13 features, epoch, optimizer, generator,
history. `load_checkpoint` từ chối sai config/method/schema, sai checksum hoặc
file hỏng (`CheckpointError`). Reload parity trong process ≤ `1e-7`; parity
môi trường mới thuộc M6.1.

## Lệnh chạy

```bash
# Software verification trên fixture tổng hợp
python scripts/run_m24_pipeline.py --config configs/m2.4/pipeline.toml \
  --method QPAF --synthetic-fixture --output results/m2.4/<run-dir>

# Dữ liệu thật khi cache M2.8 sẵn sàng
python scripts/run_m24_pipeline.py --config configs/m2.4/pipeline.toml --method QARF \
  --scores <cache.parquet> --queries <queries.json> --qrels <qrels.json> \
  --splits evidence/revisions/m1.3-001/splits --output results/m2.4/<run-dir>
```

Mỗi run dùng `StageRun` (M1.1): `resolved_config.json`, `provenance.json`,
`data_manifest.json`, `epochs.csv`, `steps.csv`, `checkpoints/`,
`validation_predictions.json`, `validation_per_query.csv`,
`validation_metrics.json`, `telemetry.json` (thời gian + peak RSS theo phase),
`summary.json`, `report.md`, `hashes.csv`, `receipt.json`. Run lỗi giữ thư mục
attempt với `status.json = failed` và `failure.json` (loại lỗi, traceback).

## Giới hạn

- Chưa có cache điểm ViDoSeek toàn corpus (M2.8), nên chưa có run dữ liệu thật.
- Fixture tổng hợp chỉ chứng minh đường phần mềm, không phải kết quả retrieval.
- Latency/memory gate của metric policy đo ở M3+, không ở đây.
