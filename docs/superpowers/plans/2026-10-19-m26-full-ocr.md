# M2.6 Full OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Execute and verify the frozen full-corpus OCR bundle for 5,385 ViDoSeek pages.

**Architecture:** Dedicated full-run orchestration around existing M2.3 extraction/routing helpers, with pinned CPU-only Modal runtime and locally verified downloads. Preserve M2.4 page identities and M2.5 frozen split isolation.

**Tech Stack:** Python 3.11, PDFium 4.30.0, Tesseract 5.3.0, Pillow 11.3.0, psutil 7.0.0, Modal 1.5.5.

**Spec:** `docs/superpowers/specs/2026-10-19-m26-full-ocr-design.md`

## Global Constraints

- 292 PDFs / 5,385 pages; preserve all scheduled IDs and failed rows.
- Frozen M2.3 policy SHA `c0fcf0b3b13b27070716179d75545ba33ae406cc99a74902737bcf2dad19c4b8`.
- 300 DPI, OEM 3 / PSM 3 / eng, two workers, one subprocess thread, 15s OCR timeout.
- Four CPU cores, 4,096 MiB, 40,000,000 pixels; technical failure fraction <=0.01.
- Preserve frozen evidence and test split; no training, score cache or retrieval claims.

## Review Focus

- Render failures must still contribute to the all-scheduled-pages denominator.
- Artifact omission or path traversal must make verification fail.
- Native-preserving fusion must be reproducible from saved raw inputs.
- A complete ID count must not hide duplicate or wrong-document pages.
- Downloads or process interruptions must not overwrite immutable completed work.
