# M4.7 G2A Freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write a create-once, verifiable G2A record that freezes QPAF-v1, its config, checkpoints, baselines, the ViDoSeek test-172 held-out contract and the R1–R10 roster, without running anything.

**Architecture:** `src/qpaf/m47/roster.py` holds the roster and its rules; `src/qpaf/m47/g2a.py` checks prerequisites and pins, replays M4.3/M4.6 in child processes, and creates or verifies `evidence/revisions/m4.7-001/`. A thin CLI in `scripts/freeze_m47_g2a.py`.

**Tech Stack:** Python 3.13.7 standard library plus `qpaf.m43.freeze` helpers; `unittest`. Run with `.venv/Scripts/python.exe -X utf8`.

**Spec:** `docs/superpowers/specs/2026-10-24-m47-g2a-freeze-design.md`

## Review Focus

- A replay child that exits 0 but prints no JSON, or JSON without `"status": "PASS"`, must refuse, not pass.
- A roster entry whose `allowed_data` mentions test in any spelling other than R7 (`'test'`) must refuse.
- A pinned file that is missing must name its path, like a hash mismatch does.
- `--verify` from a later commit that descends from the creating commit must pass; from an unrelated commit it must refuse.
- Running `--output-dir` twice must refuse before any replay starts, so no work is wasted.
